## 1. 版本路线（统一口径）

当前 `Cargo.toml` 为 `0.1.0`，M0–M7 成果全部停留在 `CHANGELOG [Unreleased]`。原 §7 版本规划（M7⇒1.0.0）与 §13「0.2.0 候选」口径冲突，现统一为**连续 0.x 序列**：

| 版本 | 承载内容 | 里程碑 | 性质 |
| :--- | :--- | :--- | :--- |
| `0.1.0` | 最初基线（前端 + VM + Fuel + 嵌入 API） | 基线 | 已标记 |
| `0.2.0` | M0–M7 全部成果 + §13 后续缺口（T8.1–T8.5） | M0–M7 | 稳健化 + 工具链（向后兼容） |
| **`0.3.0`** | **M8 · 模块系统与结构化数据（本计划）** | **M8** | **含破坏性变更**（内置模块显式导入） |
| `0.4.0`+ | JIT（T6.4）、被捕获顶层变量镜像（T8.5）等 | 后续 | 演进 |
| `1.0.0` | API 冻结、生态成熟 | — | 稳定 |

**规则**：
- `0.x` 期间允许 `minor` 版本承载破坏性变更（semver 0.x 约定），故内置模块显式化落在 `0.3.0` 而非 `2.0.0`。
- §7 原「M7⇒1.0.0」作废；`1.0.0` 只保留给「API 冻结」。
- `Cargo.toml` / `CHANGELOG` 在**发布该版本时**才推进版本号；当前仍处 `Unreleased`。

## 2. M8 目标与退出标准

**目标**：让 Ada-D 具备多文件组织能力与结构化数据惯用法，并统一内置模块的获取方式为显式导入。

**退出标准（全部满足才可发布 0.3.0）**：
1. 文件 import 全链路可用且**默认安全**（无 resolver/root 时拒绝）。
2. 内置模块**必须显式导入**才可用；命名空间与具名两种形式均支持。
3. 全局函数（`print`/`len`/`type_of` 等）保持隐式可用。
4. 结构体惯用法（构造/方法/`deep_eq`/`clone`/`has_keys`/`assert_keys`）可用并有测试。
5. 现有约 **213 处** `模块.函数` 用法完成迁移，`cargo test --workspace` 全绿。
6. `cargo fmt --check` + `cargo clippy -D warnings` 通过。
7. SPEC/AI_GUIDE/CHANGELOG 同步；破坏性变更**醒目标记**。
